# План отказоустойчивости и переключения

## Сценарии

### Отказ зоны AZ в af-south-1

- **Обнаружение:** health checks, алерты Prometheus (P1)
- **Решение:** автоматика, без человека
- **Шаги:** Application Load Balancer перераспределяет трафик на приложение во второй AZ; смена мастера
- **Время:** < 5 мин
- **Потери данных:** 0 (синхронная репликация)

### Отказ всего региона af-south-1

- **Обнаружение:** внешние health checks + отсутствие метрик (P1)
- **Решение принимает:** дежурный по runbook через 15 мин, эскалация к CTO
- **Подготовка заранее:** кроссрегиональные копии снапшотов PostgreSQL и WAL-архив в S3 eu-west-1 (ПДн-схемы Кении/ЮАР зашифрованы), окружение описано в Terraform, постоянные ноды не запущены
- **Шаги переключения:**
  1. Каталог и витрина продолжают отдаваться из CDN/edge-кеша и клиентского кеша - read-only режим без ручного вмешательства
  2. запуск terraform окружения в eu-west-1
  3. Восстановление PostgreSQL из последнего снапшота + накат WAL до точки отказа
  4. Предпрогрев Redis из последнего снапшота
  5. Переключение DNS на eu-west-1
  6. Узел ПДн в Лагосе не затронут - регистрация и заказы нигерийцев работают после поднятия приложения
- **Время:** RTO целевое 4-8 часов (восстановление БД наиболее затратный этап)
- **Потери данных:** платежный журнал - до 15 мин (WAL-архив); каталог и ПДн Кении/ЮАР - до 24 ч (последний снапшот)

### Отказ узла ПДн в Лагосе

- **Обнаружение:** health checks модуля ПДн из облака, алерт P1
- **Решение:** автоматизация, при полной потере площадки привлечение CTO
- **Шаги:**
  1. Промоушен реплики PostgreSQL ПДн, переключение модуля ПДн на standby инстанс
  2. При недоступности всего узла: регистрация и оформление заказов нигерийцев останавливается с явной ошибкой; каталог, заказы Кении/ЮАР, платежный журнал работают
  3. Восстановление из локального бэкапа на резервной площадке внутри Нигерии
- **Время:** промоушен реплики < 15 мин автоматически; восстановление площадки из бэкапа - 4-8 часов
- **Потери данных:** до ~5 мин (асинхронная реплика); платежный журнал не затрагивается

### Потеря сетевой связности облако <-> Лагос

- **Обнаружение:** рост ошибок/таймаутов вызовов модуля ПДн, алерт P1
- **Решение:** автоматика (circuit breaker)
- **Шаги:**
  1. Circuit breaker на вызовах ПДн модуля: регистрация и оформление заказов нигерийцев с ошибкой с предложением повторить. USSD сессии завершаются с уведомлением
  2. Каталог и сценарии чтения работают без изменений
  3. При восстановлении связи автоматический возврат, ручных действий нет
- **Время:** деградация < 60 с от обрыва; восстановление - по мере готовности сети провайдера
- **Потери данных:** 0 (незавершенные заказы не создаются)

### Деградация платежного провайдера
- **Обнаружение:** рост 5xx/таймаутов API провайдера, алерт P1
- **Решение:** автоматика (circuit breaker)
- **Шаги:**
  1. Нигерия: переключение инициации платежей между Paystack и Flutterwave
  2. Кения: резервного провайдера нет до месяца 6  - платежи ставятся в очередь повторных попыток, покупателю показывается статус "платеж обрабатывается"
  3. Отложенные платежи дозавершаются после восстановления провайдера
- **Время:** переключение в Нигерии - секунды (автоматика); Кения - зависимость от провайдера
- **Потери данных:** 0 (идемпотентность, очередь повторных попыток)
