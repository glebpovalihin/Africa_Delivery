# ADR-003. Стратегия размещения данных

- **Статус:** предложено
- **Дата:** сентябрь 2026
- **Срок пересмотра:** сразу после получения заключения Nwosu & Partners до 15.10
- **Связанные документы:** ADR-001, `data-residency-map.md`, `cloud-regions-comparison.md`, противоречия 5 и 6 (Task1)

## Контекст

Юристы рекомендуют не финализировать архитектуру до их заключения, но дата запуска 15.10 зафиксирована, заключение будет только через 4-6 недель.
Точно известно что ПДн граждан Нигерии должны хранится в стране, по Кении требования "близкие к локализации", POPIA требует подтверждаемого управления согласиями с первого дня.
Неизвестно: точный объем "ПДн", сроки хранения, статус псевдонимизированных данных

## Решение

**Топология**
1. Stateless ядро (каталог, заказ, оркестрация, уведомления, аналитика) в AWS af-south-1
2. ПДн граждан Нигерии - отдельный узел в Лагосе у локального провайдера MDXi
3. ПДн граждан Кении и ЮАР - в af-south-1, в отдельных схемах БД с отдельными ключами
4. Платежные реквизиты не хранятся - токенизация у лицензированных провайдеров
5. Связь облако - узел ПДн: mTLS, только вызовы API модуля ПДн

**Маскирование и псевдонимизация:**
- Вся выгрузка данных за пределы контура страны проходит только через модуль data gate внутри монолита
- Псевдоним = HMAC(user_id, соль)
- Заказ в облачной БД ссылается на покупателя по псевдониму, связка псевдоним-личность существует только на узле страны
- Логи - форматтер data gate маскирует телефоны/адреса на записи

**Шифрование и управление ключами**
- Передача: TLS 1.3; контур ПДн - mTLS
- Хранение: AES-256
- Ключи раздельные по контурам и странам
- Ротация ключей - раз в квартал, выполняется автоматизированно

**Репликация**
- Облачная PostgreSQL - реплика в другой AZ, платежный журнал - синхронная репликация
- БД ПДн в Лагосе - асинхронная реплика на второй площадке внутри Нигерии (RPO ~5 мин)
- Бэкапы - ПДн Нигерии только в Лагосе, облачные в af-south-1 без ПДн. Кросс-региональная копия не создается: риск полной потери региона принят в failover плане

**Сроки хранения**
- ПДн: срок жизни аккаунта + удаление/обезличивание по запросу субъекта
- Логи: 30 дней
- Платежный журнал: 5 лет (финансовая отчетность)
- Записи согласий: срок жизни аккаунта + 1 год для аудита

## Обратимость решения

1. Граница данных фиксируется в политиках, а не в коде (конфигурация data-gate). Изменение требований - смена политики и миграция данных без разработки
2. При возникновении требования  вывода ПДн Кении в локальный узел - развертывание копии узла по готовому IaC + миграция одной схемы БД в которой уже изолированы ПДн
3. Смена облачного региона/провайдера - используются IaC (Terraform), контейнеры, стандартные протоколы что позволяет переключиться в рамках недели
4. Ослабление требований при ответе юристов приведет к упрощению  политик data gate
5. Узел в Лагосе требуется разработать на том же стеке  что и основной (Go, PostgreSQL) - переносится на любого провайдера, включая будущий регион гиперскейлера в Нигерии, без переписывания

## Альтернативы

1. **Все данные в Нигерии** Отклонено: у локальных провайдеров нет managed-сервисов, нужных для прототипа, SLA ниже, рост заблокирован
2. **Все данные в af-south-1 с шифрованием** Отклонено: шифрование не снимает требование локализации NDPR; риск блокировки регулятором и штрафов
3. **Ждать заключения юристов до старта проектирования** Отклонено: заключение через 4-6 недель, дата 15.10 зафиксирована, риск не уложиться в сроки

## Последствия

**Позитивные:**
- Запуск 15.10 без нарушения уже известных требований
- Уточнение юристов в худшем случае приведет к пересмотру политик

**Негативные:**
- +1 площадка в эксплуатации (Лагос) при 6 контракторах
- Latency вызова ПДн модуля Лагос из af-south-1 (~150 мс) добавляется к операциям регистрации и оформления заказа нигерийцев
