# Transition Architecture

## Состояние сейчас

- отсутствие кодовой базы, инфраструктуры, договоров
- Принятые решения: ADR-001 (монолит), ADR-002 (кеширование), ADR-003 (размещение данных), ADR-004 (платежи)

## Переход сейчас -> MVP

| Что появляется | Как минимизируются последующие изменения |
|---|---|
| Go-монолит с модулями: каталог, заказ, платежная оркестрация, уведомления, интеграции, согласия, data gate, ПДн модуль | Границы модулей совпадают с границами будущих сервисов  |
| Инфраструктура: AWS af-south-1 + узел ПДн в Лагосе  | Все поднимается по IaC (Terraform) - воспроизводимо для новых регионов и узлов  |
| Провайдеры за абстрактными интерфейсами (платежи, логистика, уведомления) | Новый провайдер или страна - новый адаптер, а не переработка ядра |
| Каналы: Android + PWA, USSD, WhatsApp онбординг | Общий бэкенд, новые клиенты не меняют серверную часть |
| Наблюдаемость (Prometheus/Grafana, алерты P1-P3) | Стек OTel не привязан к вендору |

## Состояние MVP (15.10.2026)

- Go-монолит: каталог, заказ, платежная оркестрация (клиенты провайдеров), уведомления, интеграции, согласия, data gate, ПДн модуль
- AWS af-south-1: managed PostgreSQL, Redis, SQS, S3, CloudFront, узел ПДн в Лагосе
- Android + PWA, USSD канал, WhatsApp онбординг продавцов
- Наблюдаемость: Prometheus/Grafana, алерты P1-P3
- Нагрузка: 50k DAU, 2k заказов/день, 2 страны

## Переход MVP -> 12 мес

| Что меняется | Как минимизируются последующие изменения |
|---|---|
| Поиск с опечатками | текущий PG FTS дополняется триграмными индексами |
| Кабинет продавца с аналитикой | Новый PWA-раздел поверх существующего API модуля "продавцы", аналитика через SQL поверх платежного журнала и заказов |
| Прямая интеграция M-Pesa | Третий клиент в модуле платежной оркестрации рядом с Flutterwave/Paystack, интерфейс провайдера уже абстрагирован |
| Пересмотр ADR-003 по заключению юристов | Смена политик data gate |
| Отзывы с видео, колесо фортуны, реферальная программа | Новые модули/эндпоинты того же монолита |
| Подключены новые страны | Через конфигурацию, а не код: валюта, язык, провайдеры за абстрактными интерфейсами|
| B2B-режим | Отдельный модуль монолита  поверх тех же каталога и заказа |
| Аналитическая реплика (OLAP) | Асинхронная выгрузка через data gate, снижение нагрузки на транзакционную БД |
| Антифрод через ML | Правила дополняются скорингом на накопленных данных |
| iOS | Решение по данным аудитории PWA, отдельный клиент  на основе того же бекенда |

## Состояние 12 мес

- 5 стран, ПДн по странам за контурами
- Тот же монолит, выросший по модулям; точка пересмотра архитектурного стиля - 3M активных пользователей или 2 год
- B2B-режим, кабинет продавца с аналитикой, аналитическая реплика
- Прямая интеграция M-Pesa для Кении
- Нагрузка: 200k заказов за 1 год, рост к плану 2 года
